# C4 diagrams

C4 model of the **current** architecture: a hexagonal Spring Boot monolith with PostgreSQL, a
React + TypeScript frontend, and the external Badminton Vlaanderen portal. Facts are taken
from `docker-compose.yml` and the architecture section of
[`DOCUMENTATION.md`](../../DOCUMENTATION.md). The planned mobile app is intentionally omitted
until it exists.

## Level 1 — System context

```mermaid
C4Context
    title System context — Better Badminton Vlaanderen
    Person(player, "Player / Club / Administrator", "Badminton community in Flanders")
    System(bbv, "Better Badminton Vlaanderen", "Companion app that adds what the portal lacks")
    System_Ext(portal, "Badminton Vlaanderen portal", "Official portal and data (badmintonvlaanderen.be)")
    Rel(player, bbv, "Uses", "HTTPS")
    Rel(bbv, portal, "Reads data from", "HTTPS")
```

## Level 2 — Containers

```mermaid
C4Container
    title Containers — Better Badminton Vlaanderen
    Person(player, "Player / Club / Administrator", "Badminton community in Flanders")
    System_Boundary(bbv, "Better Badminton Vlaanderen") {
        Container(web, "Web frontend", "React + TypeScript", "Ranking, tournament and scenario UI")
        Container(api, "Backend", "Java 17, Spring Boot — hexagonal monolith", "Business logic and REST API")
        ContainerDb(db, "Database", "PostgreSQL 15", "Persists application data")
    }
    System_Ext(portal, "Badminton Vlaanderen portal", "Official portal and data")
    Rel(player, web, "Uses", "HTTPS")
    Rel(web, api, "Calls", "JSON / HTTP :8080")
    Rel(api, db, "Reads & writes", "JDBC :5432")
    Rel(api, portal, "Fetches data from", "HTTPS")
```

## Level 3 — Components (backend)

> Drawn at the documented hexagonal-layer granularity (`infrastructure` / `application` /
> `domain`). The backend currently holds configuration only, so concrete components are
> illustrative of the layer structure. <PLACEHOLDER> — refine into real components as the
> backend is implemented; keep the layer dependencies (infrastructure → application →
> domain; application never imports infrastructure).

```mermaid
C4Component
    title Components — Backend (hexagonal layers)
    Container_Boundary(api, "Backend — Spring Boot monolith") {
        Component(webc, "Web adapters", "REST controllers, DTOs", "Infrastructure")
        Component(portalAdapter, "Badminton Vlaanderen adapter", "HTTP gateway", "Infrastructure")
        Component(persistence, "Persistence adapters", "JPA repositories", "Infrastructure")
        Component(app, "Application services & ports", "Use cases, interfaces", "Application")
        Component(domain, "Domain model & services", "Entities, value objects, rules", "Domain")
    }
    ContainerDb(db, "PostgreSQL 15", "Database")
    System_Ext(portal, "Badminton Vlaanderen portal", "External API")
    Rel(webc, app, "Invokes use cases")
    Rel(app, domain, "Uses")
    Rel(app, persistence, "Depends on repository port")
    Rel(app, portalAdapter, "Depends on gateway port")
    Rel(persistence, db, "Reads & writes")
    Rel(portalAdapter, portal, "Fetches from")
```
